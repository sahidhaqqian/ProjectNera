# Audio Reactive Dance V1.1

Implemented on `codex/animation-manager-redesign`. Settings enables detection; Windows evidence determines music; PetBehavior selects only the curated Dance Pool.

1. **Windows API:** read-only GSMTC (`GlobalSystemMediaTransportControlsSessionManager`). Polls playing sessions/source identity/title/artist/album/playback type; never sends playback controls. [Microsoft API](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession).
2. **Output capture:** WASAPI shared-mode default multimedia **render** endpoint with `AUDCLNT_STREAMFLAGS_LOOPBACK`; accepts float32 and PCM16/24/32. No microphone, recording files, uploads or music import. Endpoint changes and failures retry with bounded delays. [Microsoft loopback documentation](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording).
3. **Media score:** Playing, source, title, artist, album and Music type are preserved, including type from playback-info or media properties. Chromium also reports `PlaybackType::Music` for ordinary videos/Shorts, so the flag alone is insufficient outside dedicated music players. Title plus a creator/channel in the Artist field is also insufficient. Strong structured metadata means title + artist + album without a spoken-content hint. Music title hints include `music`, `official audio`, `official video`, `lyric video`, `lyrics`, `soundtrack`, `lofi` and `bgm`; spoken hints such as `tutorial`, `podcast`, `interview`, `lecture`, `how to`, `explained` and `news` prevent metadata promotion outside dedicated players. Missing properties retain useful playing/source evidence.
4. **DSP:** downmix/low-pass/8 kHz analysis, 32 ms Hann frames, 12 spectral bands, RMS, positive spectral flux, spectral concentration/distribution and rhythmic correlation. Stores a short frame plus four seconds of feature history only.
5. **Fusion:** Playing + active output + dedicated player or strong structured music metadata qualifies for HIGH. Music type + music title hint + title/artist also qualifies for HIGH. A music title hint without spoken hints plus DSP probability ≥0.45 qualifies for MEDIUM. Generic metadata, including browser Music type + title/channel alone, remains AMBIGUOUS and DSP-dependent. HIGH fusion uses 80% media / 20% DSP with a 0.72 floor; MEDIUM uses 70% / 30%; ambiguous browser fusion uses 90% DSP / 10% capped media evidence, while other playing sources use 85% / 15%. Inactive output produces zero confidence. Media-only fallback accepts dedicated players; audio-only fallback remains possible. Both unavailable produces no music.
6. **Hysteresis:** the global start threshold stays ≥0.70, sustained for **HIGH: 0.5 seconds / MEDIUM: 1 second / AMBIGUOUS: 2.5 seconds**. Confirmed music uses the lower 0.45 hold threshold and a **4-second** stop delay. `MusicDetectionState` tracks current/confirmed source-title-artist-album identity: a different item must earn its own start evidence before inheriting the music hold policy. Scrolling weak Shorts cannot keep refreshing the stop grace period or pool start time across items. Returning to the same confirmed song during a brief pause preserves its hold behavior. Unconfirmed tier changes reset start accumulation. Timings count fresh observations; polling, DSP warmup, avatar loading and higher-priority states can delay visible dancing.
7. **Threads/CPU:** separate bounded Media Session and WASAPI observers; Bevy consumes one latest-value mailbox at 4 Hz using try-lock. Native APIs and DSP never execute on the render thread. Optimized standalone DSP analyzed 5 seconds of synthesized signal in ~2.8 ms; this is not a whole-app CPU measurement.
8. **Ownership:** AutoDance is priority 35 inside `NeraAnimationState`, mapped to existing library playback. PetBehavior only selects/requests; LibraryPlayback validates/loads/retargets and supplies real duration. No second AnimationPlayer path. Completion selects the next clip without immediate repeats; invalid clips are skipped until the pool changes/replacement resets selection.
9. **Interruption:** standing-compatible states only; walking exits through existing runtime cancellation. Sitting, both Cloud modes, dragging, startup/loading, Alarm/Attention, utility/manager ownership and manual animations block AutoDance. Music evidence continues while blocked. Stop/OFF releases only AutoDance; normal state resolution restores the correct owner. Character replacement discards old clip/selection references while preserving pool/preference/body mode.
10. **Dance Pool storage:** `%APPDATA%/ProjectNera/dance_pool.json`, curated registry-relative VRMA references, bounded and deduplicated. The tested installation has two user-selected production clips, unchanged: `Clawatar_animations/4_Belly Dance.vrma` (19.625 seconds) and `Mixamo-VRMA/Breakdance_Freeze_Var_1.vrma` (4.125 seconds). Two entries are a validation fixture, not a required pool size. No dance asset copies are required. Bookmark moves/rename remap references; deletion removes them. Empty/missing/unplayable pools reserve no pose and log once while waiting.
11. **Manager UI:** existing Animation Manager gets a Dance tab. `+ Dance` / `- Dance` on animation cards adds/removes existing library or bookmark clips, including protected previews. The existing preview/play action remains intact; pool changes reach the pet over existing worker/host IPC.
12. **Settings:** Audio → Audio Reactive Dance ON/OFF, default OFF, persisted through the existing settings schema. Global sound mute/volume remains independent of Windows detection.
13. **Files:** new `src/music.rs`, `src/music/{native,dsp,tests}.rs`, `src/dance_pool.rs`, `src/pet_behavior/dance.rs`; modified `Cargo.toml`, `src/main.rs`, `src/pet_behavior.rs`, `src/animation.rs`, `src/animation/{library,state}.rs`, `src/animation_manager.rs`, `src/animation_manager/{registry,ui,process}.rs`, `src/settings/{model,ui,runtime}.rs`, `src/cloud/tests.rs`, `ARCHITECTURE.MD`. Settings runtime change only extends an existing test fixture. Chibi/touch implementations and all existing regressions remain intact.
14. **Tests:** existing media/DSP, Dance Pool, ownership, Cloud, Chibi, character replacement, manager and preference regressions remain intact. Fourteen focused detector tests passed, including all start tiers, misleading browser Music flags/channel metadata, song-to-scrolling-Shorts transitions and confirmed-song pause/resume. Nine focused AutoDance tests passed, including two-entry no-repeat selection, uninterrupted hover, captured pointer gestures and headpat takeover. Latest validation on **2026-10-05**: `cargo fmt`, `cargo check` and complete `cargo test` passed: **493 passed, 0 failed, 8 ignored** (six pre-existing and two opt-in native tests). Logs: `target/music-hover-check.log`, `target/music-hover-tests.log`. Native rebuild output is recorded in `target/music-hover-build.log`.
15. **Native validation performed:** persisted pool loaded both production clips and saved detection was ON. Real YouTube [Coldplay — Adventure Of A Lifetime](https://www.youtube.com/watch?v=QtXby3twMmI) triggered MusicDetected and actual native library playback. Both dances played, completed and alternated without immediate repeat; pausing music produced MusicStopped and idle restoration (`target/music-v11-pet-error.log`). The exact spoken [Shorts case](https://www.youtube.com/shorts/F6sY5bZn1DE) reproduced the old false positive despite only moderate DSP. After rebuild/restart, the live native probe stayed `music=false` and Nera remained in normal idle behavior; rechecking Coldplay still triggered AutoDance, and returning to Shorts left it non-music (`target/music-shorts-native.log`, `target/music-shorts-pet-error.log`). Native navigation included a playback/loading gap: continuous-audio media-change grace behavior is proven by regression tests, not an independently timed gap-free native handoff. Dedicated-player music, broader spoken-video samples and notification/call/game scenarios were not manually validated. The earlier generated-tone fixture failed its silent-output precondition before playing any signal; that historical result is not a real YouTube/Dance Pool validation.
16. **V1.1 limits:** heuristic recognition can miss nonrhythmic/quiet/complex music or misclassify rhythmic effects/podcasts. Music with sparse metadata can require the slower DSP path. This is not a URL-based Shorts blacklist; genuine music in a short clip may still qualify. Global endpoint audio cannot reliably associate every sound with one Media Session. Output routed to a non-default device is not observed. Seated/Cloud dancing is postponed according to existing ownership.

## Pointer interaction

Pointer hover alone does not interrupt or restart AutoDance. Its pointer gate accepts None/Hover while preserving the stricter existing roaming gate. Left/right mouse capture, dragging and recognized headpat/touch reactions still yield to the existing interaction/animation owner. Regression coverage checks hover enter/leave with the original clip lifetime, captured gestures and headpat takeover.

## Diagnostics

Logs record `MusicDetected` / `MusicStopped`, selected dance paths and accepted playback duration. Evidence changes are logged at most once every two seconds: source, Playing, Music type, metadata presence, media score, active output, DSP probability, final confidence and tier. `NERA_MUSIC_DIAGNOSTICS` adds a five-second evidence heartbeat. Production evidence logs do not print raw titles or audio samples every frame.
