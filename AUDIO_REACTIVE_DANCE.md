# Audio Reactive Dance V1

Implemented on `codex/animation-manager-redesign`. Settings enables detection; Windows evidence determines music; PetBehavior selects only the curated Dance Pool.

1. **Windows API:** read-only GSMTC (`GlobalSystemMediaTransportControlsSessionManager`). Polls playing sessions/source identity/title/artist/album/playback type; never sends playback controls. [Microsoft API](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession).
2. **Output capture:** WASAPI shared-mode default multimedia **render** endpoint with `AUDCLNT_STREAMFLAGS_LOOPBACK`; accepts float32 and PCM16/24/32. No microphone, recording files, uploads or music import. Endpoint changes and failures retry with bounded delays. [Microsoft loopback documentation](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording).
3. **Media score:** positive dedicated-player hints plus playing/artist/album metadata. Browser metadata remains weak; keywords alone cannot start dancing. Missing properties retain the playing/source evidence.
4. **DSP:** downmix/low-pass/8 kHz analysis, 32 ms Hann frames, 12 spectral bands, RMS, positive spectral flux, spectral concentration/distribution and rhythmic correlation. Stores a short frame plus four seconds of feature history only.
5. **Fusion:** dedicated playing media plus active audio is strong. Browser/unknown/no metadata requires stronger audio evidence. Media-only fallback accepts dedicated players; audio-only fallback remains possible. Both unavailable produces no music.
6. **Hysteresis:** confidence ≥0.70 for 3 seconds starts; confidence <0.45 for 4 seconds stops. Brief silence does not flap. Audio warmup may add roughly 2 seconds before browser/audio-only evidence becomes useful.
7. **Threads/CPU:** separate bounded Media Session and WASAPI observers; Bevy consumes one latest-value mailbox at 4 Hz using try-lock. Native APIs and DSP never execute on the render thread. Optimized standalone DSP analyzed 5 seconds of synthesized signal in ~2.8 ms; this is not a whole-app CPU measurement.
8. **Ownership:** AutoDance is priority 35 inside `NeraAnimationState`, mapped to existing library playback. PetBehavior only selects/requests; LibraryPlayback validates/loads/retargets and supplies real duration. No second AnimationPlayer path. Completion selects the next clip without immediate repeats; invalid clips are skipped until the pool changes/replacement resets selection.
9. **Interruption:** standing-compatible states only; walking exits through existing runtime cancellation. Sitting, both Cloud modes, dragging, startup/loading, Alarm/Attention, utility/manager ownership and manual animations block AutoDance. Music evidence continues while blocked. Stop/OFF releases only AutoDance; normal state resolution restores the correct owner. Character replacement discards old clip/selection references while preserving pool/preference/body mode.
10. **Dance Pool storage:** `%APPDATA%/ProjectNera/dance_pool.json`, curated registry-relative VRMA references, bounded and deduplicated. No production dance files selected/copied. Bookmark moves/rename remap references; deletion removes them. Empty/missing/unplayable pools reserve no pose and log once while waiting.
11. **Manager UI:** existing Animation Manager gets a Dance tab. `+ Dance` / `- Dance` on animation cards adds/removes existing library or bookmark clips, including protected previews. The existing preview/play action remains intact; pool changes reach the pet over existing worker/host IPC.
12. **Settings:** Audio → Audio Reactive Dance ON/OFF, default OFF, persisted through the existing settings schema. Global sound mute/volume remains independent of Windows detection.
13. **Files:** new `src/music.rs`, `src/music/{native,dsp,tests}.rs`, `src/dance_pool.rs`, `src/pet_behavior/dance.rs`; modified `Cargo.toml`, `src/main.rs`, `src/pet_behavior.rs`, `src/animation.rs`, `src/animation/{library,state}.rs`, `src/animation_manager.rs`, `src/animation_manager/{registry,ui,process}.rs`, `src/settings/{model,ui,runtime}.rs`, `src/cloud/tests.rs`, `ARCHITECTURE.MD`. Settings runtime change only extends an existing test fixture. Chibi/touch implementations and all existing regressions remain intact.
14. **Tests:** 18 added automated regressions cover media scoring/fusion, silence/tone/rhythmic/noise DSP, start/hold/stop hysteresis, empty/missing/no-repeat pools, ownership cancellation/one-shot completion, manual playback, both Cloud modes, character replacement in Normal/Chibi, pool CRUD/remapping/persistence, manager actions/preview/IPC and preference restoration. Two additional opt-in native probes. `cargo fmt` and `cargo check` passed; complete `cargo test`: **480 passed, 0 failed, 8 ignored** (six pre-existing and two opt-in native tests). Logs: `target/music-check-final.log`, `target/music-tests.log`.
15. **Native validation performed:** eight-second live Windows probe passed. GSMTC read a currently playing browser session; WASAPI read active mixed output; detector remained below its start threshold. `target/music-native.log` records evidence. The opt-in silence/generated-music/stop fixture failed its **silent-output precondition** because other audio was playing; it did not play its generated signal. See `target/music-loopback.log`. No existing playback was paused. Dedicated-player music, verified YouTube music/speech, notification/call/game cases and a full native dance sequence were not manually verified.
16. **V1 limits:** heuristic recognition can miss nonrhythmic/quiet/complex music or misclassify rhythmic effects/podcasts; global endpoint audio cannot reliably associate every sound with one Media Session. Output routed to a non-default device is not observed. Browser/audio-only detection is deliberately conservative. Seated/Cloud dancing is postponed. Fill the Dance Pool before expecting actual dance playback.
